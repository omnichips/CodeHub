# We Might As Well Die Trying (Die Trying): game notes

Top-down horde-defence game, Phaser 3.90 + TypeScript + Vite, pixel art drawn in code. Live at
https://chips-codehub.vercel.app/dietrying/. Read the repo-root `AGENTS.md` first: its rules (never commit unasked, test
only what's in scope, deploy verification) apply here.

**Trust the code and `src/data/*.json` over any note, including this one and the design doc.** The
`We Might As Well Die Trying — Game Design Document.md` is a log of settled choices, not the source of truth. The owner
keeps changing the design.

## Extra rules for this game

- **Every game commit adds an entry at the top of `src/data/patchnotes.json`**:
  `{ "date": "YYYY-MM-DD HH:MM" (Philippine time), "title": "...", "notes": ["short player-facing line", ...] }`.
  The menu's patch-notes icon shows it with a red dot until read. Get the time with
  `node -e "console.log(new Date().toLocaleString('sv-SE',{timeZone:'Asia/Manila'}).slice(0,16))"`.
- **After pushing, verify the deploy**: fetch `https://chips-codehub.vercel.app/dietrying/`, find its `assets/index-*.js`,
  grep it for a string new in the commit (the bundle hash differs from local because the build time is stamped in), and
  tell the owner. See the root file for the GitHub 403 rate-limit retry.
- **Do not balance or balance-test units** (damage, speed, prices, chips; `scripts/balance.ts`, `scripts/undefended.ts`)
  unless the owner asks; ask first. They balance by hand. Keep `npm test` green (adjusting test timing is fine).
- **Do not record TTS.** When story text in `src/data/story.json` changes, edit the text only and tell the owner the voice
  audio is out of date, with the command: `node scripts/storyvoices.ts <scene-id>`.
- Keep the New York tileset on all maps unless asked otherwise.
- Never commit `src/art/wmawdt.jfif`.

  scene.ts            Game scene: camera, touch/mouse input, driving a soldier (drive/drive_/stopDriving), HUD state
  hud.ts              HTML HUD over the canvas (status, bar, soldier card, end report, thumb stick)
  menu.ts             Menu scene: main menu, saves, binder pages, Menu.fit() scales the main menu to short screens

  settings.ts sound.ts mapart.ts mapanims.ts atmosphere.ts paper.ts pixicons.ts ...
src/meta/           profile, saves (per-map setups), medals, progress
src/story/          scene art, dialogue player, tests
src/data/           units/zombies/structures/waves/economy/story/skilltree/patchnotes JSON, maps/*.json

Maps in order: 1 Main Street, 2 Chicago, 3 New York, 4 Manila, 5 Mexico City, 6 Rome, 7 Tokyo, 8 London, 9 White House.
Every map has `scale: 2`. Maps 1-3 are hand-edited JSON; 4-9 are generated by `scripts/maps.ts`
(+ `scripts/upscale.ts`; rerun after editing a plan). Setups are kept per map in the save and auto-placed when a city
opens (Clear asks first).

## How the pieces connect

- **Driving a soldier** (play as him): the walkie-talkie button on his card calls `Game.drive()`, which sets
  `world.control = { s, dx, dy, fire }`. Each frame `drive_()` turns `held` (a Set of `w a s d`) into `dx/dy`, aims at the
  pointer, and follows him with the camera. Keyboard fills `held`; the on-screen thumb stick (HUD `.stick`, touch only,
  `@media (pointer: coarse)`) calls the HUD handler `walk(dx, dy)`, which fills `held` too. The other thumb aims/fires
  through the map pointer events. While `#hud.driving`, every HUD child drops to 10% opacity and loses pointer events;
  anything that must stay usable needs an override rule of higher specificity (see `.stick.stick`, `.drive`).
- **HUD** is plain DOM built in `Hud`'s constructor; `Hud.update(state)` is called every frame from the scene with a
  `HudState`. The end report is `.end`, filled once when `state.end` appears.
- **Menu** panels are DOM inside `#menu`; the main menu is never squashed, `Menu.fit()` sets CSS `zoom` on `.main` when
  it does not fit.

## Mobile / iPhone gotchas

- `html, body { touch-action: none }` on the page: anything that must scroll by touch needs its own
  `touch-action: pan-y` (the end report had this bug).
- iOS Safari reports its size late (on load, after rotating, as the address bar moves). Measure again on
  `visualViewport` resize, `orientationchange` and after `document.fonts.ready`, with a few delayed re-measures
  (see `main.ts` `settle` and `Menu.create`).
- Safari pinch-zooms the PAGE; `main.ts` blocks `gesturestart` and two-finger `touchmove`. HUD margins are measured
  against the canvas and `visualViewport`.
- WebKit cannot load the Vite dev server in this environment; check WebKit against the built hub
  (`node scripts/serve.mjs dist 4191` from the repo root). Playwright `text=On` also matches "None": use `text="On"`.
- Phone checks: Playwright from the root `node_modules`, CDP `Input.dispatchTouchEvent` at 844x390 against the dev
  server. Real-phone fps can only be measured on a phone.
- Balance sims are headless node scripts importing `World`; large maps are slow, so one map per process.
